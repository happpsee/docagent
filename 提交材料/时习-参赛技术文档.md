## 一、作品简介

### 1.1 一句话说明

时习是一个**会主动考你的阅读器**：你读原著，它在旁边出题；你用自己的话回答，它对照原文逐条批改；每个概念掌握到什么程度它都记着，快忘了就提醒你复习。

**读了多少和学会了多少，是两个数。** 别的工具帮你读得更快，时习盯着你有没有真学会。

### 1.2 要解决的痛点

阅读的真实困难不是「查不到」，而是**读完就忘、以为懂了其实没懂**。现有产品分两类，各让一步：

| | 导师型产品（AI 讲课） | 传统阅读器 | **时习** |
|---|---|---|---|
| 谁在读 | AI 读完讲给你听 | 你自己读，但读完就结束 | 你读原文，它在旁边考你 |
| 考什么 | 讲过的知识点 | 不考 | 你刚读完的那一段，题目自动出 |
| 怎么判 | 对话里主观评估，或自评「记得/忘了」 | 无 | 模型对照原文依据逐条批改，依据点开可见 |
| 数据 | 上传云端，订阅收费 | 本地或云端 | 全在本机，开源，用你自己的 API Key |

### 1.3 核心能力

**学习闭环（本作品的主体）**

- **读完一段自动出题**：读完一段（或在一段上停留超过正常时间的三倍）触发决策点，由模型综合阅读行为与掌握度决定考几道、主动讲一讲、提醒先复习，还是什么都不做。
- **对照原文批改**：每道题出题时就带评分要点和一句原文里一字不差的依据；依据在原文中找不到的题**直接丢弃**。批改是另一次独立的模型调用，只看题目、要点、依据和你的回答，拿不准往低了判；哪条要点答到了、哪条没有，逐条列出，点一下翻回原文那一句。
- **掌握度会衰减**：每个概念一份记忆状态，用 FSRS（Anki 现用算法）排下次复习；答对的间隔越来越久，没答上来的当天再考。「学会 73%」是所有概念此刻还记得的程度的平均——不复习，它会往下掉。
- **复习换问法**：到期复习不是原题重考，同一个概念换角度再出（举例、比较、讲给外行听）。
- **掌握地图 / 记忆看板**：全书概念与关系画成图并按掌握度上色；同一份数据另一种看法是分档看板（急需复习、衰减中、记忆牢固、没考过）。
- **易错点画像**：批改中若你的回答暴露了具体误解（把甲当成了乙、因果说反），会记进「我的画像」，之后讲解按你的背景举例，复习该概念时专门检验你纠正过来没有，答对后自动划掉。
- **划线进复习**：合上书时，这一程划下的句子整理成复习题，与自动出的题排在同一个队列。
- **合书小结与书架提醒**：读了多久、读了多少、答了几题、哪些排进复习；首页提示今天该复习几个概念。

**完整的阅读器（闭环的承载体，不是附带阅读功能的聊天框）**

- 支持 **PDF / EPUB / MOBI / AZW3 / FB2 / CBZ / DOCX / Markdown / TXT** 九类格式，走同一个排版引擎，都有目录、书内搜索、书签、进度记忆、翻页或滚动、字号行距版心、四种纸色、代码块语法上色。
- **透视**：整本书逐段提取要点、人物与概念及其关系，掌握地图上的点由此而来。
- **前情提要**：隔一阵再打开读到一半的书，先用几句话帮你想起讲到哪了，且只用你读过的部分。
- **引用溯源**：回答里的每个结论带编号，点开跳到原文并高亮；资料里没有就明说没有，不编造。
- **划线与笔记**：五种颜色、三种线型，可写想法，助手回答可存回原文笔记，支持集中查看、跳回原文、导出 Markdown。
- **直接改原文**：Markdown / 文本可在阅读器内编辑，保存后写回原文件并重建索引。
- **防剧透**：小说默认开启——透视、关系图、助手都只用你读过的部分，也不会主动考你；资料与文档默认关闭。
- **通用智能体能力**：与 Claude Code 同一套工具（读写本地文件、跑命令、联网搜索、派子代理），支持技能（Skill）与 MCP 服务，所有触碰外部世界的操作都要用户点头。

桌面应用（macOS 与 Windows），单机运行，不依赖任何自建服务器。

## 三、作品安装说明

### 3.1 安装包方式（推荐，评审用这条）

**系统要求与下载**：作品提供 macOS 与 Windows 两个平台的安装包，均在 https://github.com/happpsee/docagent/releases/latest 下载（不需要注册或登录；安装包也随提交材料一并提供）。

**macOS 版**（Apple 芯片，macOS 10.13 及以上）

1. 取得安装包 `Shixi_0.1.0_aarch64.dmg`（约 41 MB）。
2. 双击打开，将 **时习** 拖入「应用程序」。
3. **首次打开**：因作品未做苹果开发者签名，双击后如提示「无法打开」，请到 **系统设置 → 隐私与安全性**，在下方找到时习的提示，点击 **「仍要打开」**，再次确认即可。此操作只需一次。

**Windows 版**（64 位 Windows 10 1809 及以上，或 Windows 11）

1. 取得安装包 `Shixi_0.1.0_x64-setup.exe`（约 41 MB）。
2. 双击运行，按向导完成安装，之后从开始菜单启动「时习」。
3. **首次运行**：若出现「Windows 已保护你的电脑」提示，点击「更多信息」，再点「仍要运行」。这是因为作品未购买代码签名证书，不是文件有问题。

**两个平台共同的首次配置**

4. **首次使用需配置模型**：打开应用后，点左下角 **设置 → 模型设置**，添加一家模型提供商并填入 API Key 与模型名（作品不内置任何 API Key，也不收取任何费用）。支持 DeepSeek、Kimi、智谱、Anthropic，以及任何 Anthropic 兼容接口；填好后点「测试连接」确认可用。
5. **（可选）配置向量接口**：若要启用语义检索，在同一设置页填写向量接口的地址、Key 与模型名；**不配置也可正常使用**，此时检索走中文全文检索。
6. **（可选）演示数据**：将仓库 `test-docs/` 下的四个示例文件（`采购合同.pdf`、`采购合同.md`、`服务协议.md`、`示例小说.epub`）直接拖入窗口即可导入。

## 五、设计思路

### 5.1 总体设计原则

**原则一：学习闭环建在一个完整的阅读器上，而不是给聊天框加一个阅读标签页。** 阅读行为本身是学习信号的主要来源，因此阅读器必须是一等公民。

**原则二：该由代码管的，绝不交给模型。** 频率、界线、依据校验、排期算法都是确定性逻辑；模型只负责需要理解语义的环节（出题、批改、决策、讲解）。

**原则三：只让确定性的活走直连接口，只有对话走 agent。** 出题、批改、透视、前情提要是「一次调用 + 要求返回 JSON + 结果入库」，可测试、可缓存、不会因为模型多绕几步而变慢；只有真正需要工具的场景才付出 agent 的成本。

**原则四：本地优先，出网内容可枚举。** 作品不设服务端，全部数据在本机 SQLite；出网内容在文档中逐项列明（见 7.1）。

### 5.2 系统架构

作品由三个进程组成，形成一条可审计的闭环：

```
┌──────────────────────────┐
│  WebView（React 19）      │  界面 + 阅读器（foliate-js 排版引擎）
└────────────┬─────────────┘
             │ Tauri 命令 / 事件
┌────────────▼─────────────┐        stdin/stdout（每行一个 JSON）
│  Rust 后端（Tauri 2）     │◄──────────────────────────────────┐
│  · 解析 / 分块 / 索引     │                                   │
│  · 检索（全文 + 向量）    │        ┌──────────────────────────┴──┐
│  · 透视 / 出题 / 批改     │        │  sidecar（bun 单文件）        │
│  · 复习排期 / 防剧透      │        │  · 对话 agent 循环            │
│  · 管理 sidecar 进程      │        │  · 工具定义（检索/阅读器/画像）│
└────────────┬─────────────┘        │  · 工具审批闸门               │
             │                      └──────────────┬───────────────┘
             │  SQLite + sqlite-vec                │
             └──── 127.0.0.1 随机端口 + 一次性令牌 ─┘
```

**为什么这样分**：索引和文件在 Rust 侧，而 agent 的工具在 sidecar 进程里被调用，因此开一个只绑 `127.0.0.1`、端口随机、带一次性 Bearer 令牌的 HTTP 接口给 sidecar 回调。同机其他程序即使扫到端口，没有令牌也调不了。

### 5.3 学习闭环的数据流

```
读一段 ──→ 出题 ──→ 用自己的话答 ──→ 对照原文批改 ──→ 记掌握度 ──→ 到期复习
  ↑                                        │                │              │
  └──────── 点回原文 / 让助手讲没答到的 ←──┘                └── 掌握地图 ←─┘
```

各环节的确定性规则：

| 环节 | 规则 |
|---|---|
| 出题 | 每段 3 道简答题，每题考一个概念且互不重复；必须问「为什么/怎么做/有什么区别/如果……会怎样」，不出选择题与判断题；每题 2–4 条评分要点；每题必须附一句 15–60 字的原文依据 |
| 依据校验 | 把依据去掉所有空白后与原文比对，**比对不上的题整题丢弃**；若整段没出成题则明确报错，不静默降级 |
| 批改 | 独立于出题的第二次模型调用，只看题目、评分要点、原文依据与读者回答；拿不准往低了判；若判「全对」却列出超过一半要点未答到，强制降为「部分答对」；只有非全对时才记录易错点 |
| 排期 | FSRS，关闭短周期步进（读书不是背单词）；答错 10 分钟后再考，其余至少隔一天；同一概念最多攒 5 道题，之后在已有题里轮换（最久没问过的优先） |
| 复习换问法 | 到期时同一概念、同一段原文，避开已问过的角度再出一次，可换成举例、比较、说反例、解释后果、讲给外行听 |
| 掌握度 | 每个概念的掌握度 = 此刻仍能回忆的概率（FSRS 遗忘曲线）；「学会多少」= 所有概念掌握度的平均，**没考过的算 0**，上次答错的也算 0 |

### 5.4 主动性如何设计：模型决定时机，代码管住频率

打断读者是有代价的。作品把这件事拆成两半：

- **前半段（代码）**：把阅读行为整理成一份摘要——这一段的字数、实际停留秒数、按字数估算的「至少该读多久」、往回翻了几次、划了几句、就这一段问过助手几次，加上这一段考过的概念及其掌握度、全书学会百分比与待复习数、读者的画像条目、最近几次建议被接受还是被关掉。**摘要里只有数字和概念名，不含任何原文。**
- **中段（模型）**：由教练模型在此刻的决策点上决定四种动作之一——`quiz`（考他这一段）、`explain`（主动提出讲一讲）、`review`（提醒先复习到期的概念）、`none`（不打断），并给出一句 30 字以内、只依据上面事实的理由。
- **后半段（代码）**：两道建议之间至少隔一段时间（默认 10 分钟），被读者关掉一次间隔翻倍（上限 1 小时），被接受一次恢复原样；每天有上限（按档位 4 / 8 / 14 次）；同一段只问一次；即便模型说「不打断」，也要间隔 4 分钟才会再问它一次——否则每翻一页都在花钱。

于是它说出的是「这段你来回翻了三次，要不要我先讲一遍」，而不是千篇一律的「考你几道题」。

### 5.5 「这一段真读过没有」的判定

不做「翻过去就算读过」的假判定，而是四个条件的合取：

1. **只在算数的时候计时**：窗口可见、有焦点、且两分钟内有翻页或鼠标键盘动作；
2. **按字数要求最低停留时长**：每秒 20 字的快速浏览速度读一遍所需时间，最少 30 秒、最多 480 秒；
3. **覆盖要求**：把这一段按约一屏（800 字）切格（最多 8 格），至少 70% 的格子停留过，且每格停留时间不低于「平均每格应花时间」的四分之一——一闪而过不算看到；
4. **累计停留达标**：所有格子时间之和达到第 2 条的时长。

阅读时间按篇持久化在本机，关掉书下次接着算。

### 5.6 防剧透：一条规则，两处执行

小说类（EPUB/MOBI/FB2/TXT）默认开启防剧透，资料与文档默认关闭。界线的计算规则只有一份：

- 没开防剧透 → 全部不设限；
- 开了但还没开始读 → 全部不设限（此时用户多半是把它当资料查，不该什么都搜不到）；
- 开始读了 → 以「打开过的最靠后的那一篇」为准：它前面的整篇算读过，它自己只到读过的地方，它后面的整篇不给看；
- 「读到哪了」**只增不减**，且取「存下来的最远处」与「阅读器此刻位置」的较大者——往回翻不会把读过的又藏起来，刚往后翻的几页也不用等存盘。

关键在于**过滤发生在检索的 SQL 内部**，而不是检索之后再裁剪：这样每一路检索的名额、向量那一路「和最近的差多少」的参照，算的都只是用户能看的片段。范围被限制时，接口会同时回传一个 `bounded` 标志，明确告诉模型「这次没搜全，不要把搜不到说成书里没有」——这正是「引用溯源」不编造的依据。

### 5.7 检索：中文全文 + 向量两路融合

- **全文一路**：jieba 分词后写入 FTS5 倒排（只存词、不存原文，原文在 `chunks` 表），离线可用、快。
- **向量一路**（可选）：调用用户配置的向量接口，语义相近即可命中（问「逾期罚款」能找到「违约金」）。
- **融合**：每路各取 24 条，用 RRF（倒数排名融合，k=60）按**名次**计分相加，回避 BM25 分数与向量距离量纲不一致的问题；同分时按片段在库中的先后排序，保证结果稳定。
- **降级**：向量接口有 6 秒预算，超时或不可用即静默退回纯全文检索，不让用户干等；**调接口期间不持有数据库锁**。

### 5.8 智能体能力与安全边界

对话助手拥有与 Claude Code 同一套内置工具（读写文件、Bash、联网搜索、抓网页、子代理、技能等），以及本作品自有的文档工具。放开能力的同时，做了这些约束：

| 约束 | 实现 |
|---|---|
| 配置隔离 | sidecar 未指定独立配置目录时**拒绝启动**，绝不读写用户的 `~/.claude` |
| 逐次审批 | 读本地内容、写文件、跑命令、联网前都要用户点同意；一次工具调用只弹一张卡片（PreToolUse 钩子与 `canUseTool` 双重路径按调用 id 去重） |
| 记住的范围 | 「以后不再问」按目录记（读/写分开）、按**完全相同的命令**记（Bash 只记这一条）、按 MCP 服务记；换工作文件夹即全部作废 |
| 工作文件夹投毒 | 文件夹自带的 `mcp.json` 与技能意味着「打开即运行命令」，因此首次见到（或内容指纹变化）必须用户确认 |
| 落盘位置 | 助手保存的文件固定写入 `~/Documents/时习/`，文件名去掉路径成分，同名自动加序号，不覆盖用户已有文件 |
| 跨语言契约 | 本地接口的所有请求体拒绝未知字段——字段名写错或版本不匹配当场报错，而不是静默按「没传」处理（静默失效会让防剧透整个失灵） |

## 六、设计重点难点

### 难点 1：让模型不编造——「依据必须能在原文里找到」

**问题**：大模型出题时极易凭常识补出原文没有的依据，批改时也容易替读者「补上他没说的意思」。一旦发生，整个学习闭环的可信度就没了——读者点开依据发现原文根本没这句，之后不会再信任何一次批改。

**解法**（三道闸门）：

1. **出题侧硬校验**：要求每题附一句原文里一字不差的依据，程序把依据去掉所有空白后与原文做子串比对，**对不上就整题丢弃**；宁可这一段不出题，也不留下一道无法对照的题。
2. **批改与出题分离**：批改是另一次独立调用，不给它看生成时的上下文，只给题目、评分要点、原文依据和读者回答，避免「自己出的题自己护着」。
3. **矛盾降级**：若批改判「全对」却又列出超过一半的要点未答到，程序强制降为「部分答对」——用确定性规则兜住模型的自我矛盾。

**效果**：批改的每一条「没答到」都能点回原文那一句；读者可以自己核对，而不是只能相信模型。

### 难点 2：主动性——什么时候该打断，谁来定

**问题**：主动建议做重了是骚扰（每翻一页弹一次），做轻了没用；而「此刻该不该打断」高度依赖语境（读得细不细、概念牢不牢、以前在哪儿错过），写死规则必然僵化。

**解法**：把「该不该」交给模型，把「能不能」交给代码。模型只看到一份不含原文的行为摘要与掌握度，输出四种动作之一与一句话理由；频率、日上限、同段只问一次、问过模型的冷却时间全部由前端确定性规则掌握，且读者关掉一次间隔就翻倍。此外，模型给出的动作若不附理由，一律当作「不打断」。

**效果**：建议是有语境的，但读者永远有最终控制权——关掉几次它就自己安静下来。

### 难点 3：防剧透必须做在检索内部

**问题**：最直观的实现是「先检索再按进度裁掉后面的结果」。但这样一来，检索的名额已经被没读过的内容占掉了：用户读了 10%，检索却在全书的范围内取前 6 条，其中 5 条属于还没读的部分，裁掉之后只剩 1 条——用户会觉得「这本书里搜不到」。

**解法**：把界线作为查询条件下沉到两路检索的 SQL 内部（全文一路按片段序号/页码比，向量一路按距离过滤前先限定范围），使每一路的名额与参照都只针对用户能看的片段。同时回传 `bounded` 标志，让模型知道本次检索的范围被限制过。

**附带难点**：界线的状态要能处理老库升级、页码缺失（按比例比）、阅读器正在开着的这一篇（取「已存最远处」与「此刻位置」的较大者）等情况，共 6 个单元测试覆盖。

### 难点 4：掌握度必须「会掉」，且不能虚高

**问题**：如果掌握度只加不减，读者看着 90% 会以为自己学会了；如果用 Anki 式的默认参数，几分钟一轮的短周期复习会不断打断读书。

**解法**：掌握度定义为**此刻仍能回忆的概率**（FSRS 遗忘曲线，按小数天计算），而非「答对次数」。关闭短周期步进，答错 10 分钟后再考、其余至少隔一天——符合阅读场景。全书「学会多少」是所有概念掌握度的平均，**没考过的算 0**，上次答错的也记 0，因此不复习它会持续下降，且不会因为「只考过容易的题」而虚高。

### 难点 5：跨进程边界的健壮性

**问题**：三个进程（WebView / Rust / sidecar）、两种语言、两套消息协议，任何一处字段名写错或版本不一致，都可能造成静默的行为错误。

**解法**：

- 本地接口所有请求体 `deny_unknown_fields`，字段不匹配立即报错；
- sidecar 的每一次工具调用都经过闸门，钩子与 `canUseTool` 两条路径按调用 id 去重，用户只看到一张审批卡片；
- 透视提取用固定 4 个工作线程并行处理分段任务，取消、失败重试、以及「排队期间这一篇被重新导入则跳过该段」都在取文字时才校验版本号，避免写入过期结果；
- 向量补齐分批进行、每批之间释放数据库锁，界面不会被卡住；换了向量模型则整批重算。

### 难点 6：一份数据，两种可读的看法

**问题**：掌握度既要能看「哪块是空白」（知识结构视角），也要能看「现在最该做什么」（行动视角）。单一视图无法同时满足。

**解法**：同一份数据做两个视图——掌握地图（概念与关系构成图，按掌握度上色，用于看知识结构的空白）与记忆看板（按「急需复习 / 衰减中 / 记忆牢固 / 没考过」分档，用于决定现在做什么）。两者共享同一份记忆状态，任一处操作（如忽略某概念）即时反映到另一处。

## 七、其他说明

### 7.1 数据与隐私（出网内容逐项列明）

作品为本地优先应用，**不设服务端**，全部数据存放在本机。以下为全部出网内容，除此之外没有任何数据离开本机：

| 场景 | 发送内容 |
|---|---|
| 提问 | 你的问题 + 检索命中的文档片段 |
| 透视 / 出题 / 批改 / 前情提要 | 对应的那一段原文（批改时另含你的回答）；合上书时，本次新划的句子 |
| 主动建议 | 决策点上的阅读行为摘要（停留秒数、回翻次数、概念名与掌握度，**不含原文**） |
| 每次提问 | 「我的画像」中的条目（画像本身只存在本机） |
| 配置了向量接口时 | 文档片段与检索词（用于计算向量）；不配置则不发送 |

其他隐私相关事实：助手读写本地文件、跑命令、访问网页前都需用户确认；助手的配置目录是应用自己的，不读也不写用户的 `~/.claude`；助手的阅读行为计时数据保存在本机 localStorage。

**需如实说明的现状**：API Key 以明文形式存放在本机数据库中（`~/Library/Application Support/dev.local.docagent/docagent.db`），这是已知限制，作品未做额外的加密存储。

### 7.3 已知限制（如实列出）

- 出题与批改的质量取决于用户配置的模型；批改偏严是有意设计，觉得判错了可以点回原文自行核对。
- 复习排期使用 FSRS 的默认参数，尚未按个人作答记录做参数优化。
- 除 DeepSeek 外，模型目录中其他供应商的接口地址未逐一实测，建议添加后先点「测试连接」。
- 未配置向量接口时，检索只按字面匹配，同义不同词可能查不到。
- 扫描版 PDF 没有文字层：能阅读、能加书签，但无法检索、无法划线，也出不了题。
- 带 DRM 的电子书无法打开。
- 未提供朗读、翻译、词典、云同步功能。
- API Key 明文存储；macOS 与 Windows 的安装包都未做代码签名。
- **Windows 安装包由持续集成在 windows-latest 上构建产出，已确认产物是合法的 NSIS 安装器（PE 可执行文件）；但尚未在 Windows 实机上安装并走查全部功能**。未提供 Linux 安装包。
